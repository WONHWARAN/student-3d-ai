# 내 그림 3D 공작소 — 학생용 AI 3D 변환 사이트

이 버전은 학생용 화면 + 실제 Image-to-3D API 연결 구조까지 포함합니다.

## 1. 준비
- Node.js 20 이상 권장
- Meshy API 키

Meshy의 공식 Image-to-3D API는 `POST /openapi/v1/image-to-3d`로 작업을 만들고,
반환된 task ID를 조회해 `SUCCEEDED`가 되면 GLB 모델 URL을 제공합니다.
이 프로젝트는 그 방식을 사용합니다.

## 2. 설치
프로젝트 폴더에서:

```bash
npm install
```

`.env.example`을 복사해서 `.env`를 만들고 다음처럼 입력합니다.

```env
MESHY_API_KEY=본인의_Meshy_API_키
PORT=3000
MAX_CONCURRENT_JOBS=2
MAX_UPLOAD_MB=8
```

API 키는 브라우저 코드에 넣으면 안 됩니다. 반드시 서버의 `.env`에만 넣습니다.

## 3. 실행

```bash
npm start
```

브라우저에서:

`http://localhost:3000`

## 4. 40명 동시 접속
이 프로젝트에는 간단한 서버 작업 대기열이 들어 있습니다.

예를 들어 40명이 동시에 버튼을 눌러도:
- 서버는 요청을 대기열에 넣음
- `MAX_CONCURRENT_JOBS=2`라면 2개씩 AI 변환
- 각 학생은 자기 작업의 진행률을 확인
- 완성된 GLB만 자기 화면에 표시

학교에서 실제 운영할 때는 서버 재시작에 대비한 Redis/BullMQ 같은 영속 작업 큐와
파일 저장소(S3 계열 등)를 추가하는 것을 권장합니다.

## 5. 개인정보/학생 작품
학생 이름, 학번 등 개인정보를 이미지 파일명에 넣지 않는 것을 권장합니다.
현재 서버는 업로드 원본을 작업 완료 후 메모리에서 제거합니다.
외부 AI 서비스에 이미지를 전송하는 구조이므로 실제 학교 수업에서는
학교의 개인정보·AI 서비스 이용 지침에 맞춰 사용하세요.

## 6. 중요한 점
AI 3D 생성은 외부 API의 크레딧과 사용량 제한을 사용합니다.
40명이 동시에 접속하는 것과 40개의 AI 작업을 동시에 실행하는 것은 다릅니다.
따라서 대기열을 두는 것이 안전합니다.


## 7. 인터넷에서 학생들이 접속하게 배포하기

이 프로젝트는 Docker 기반 Render Web Service 배포 파일(`render.yaml`, `Dockerfile`)도 포함합니다.

### 가장 쉬운 배포 순서
1. 프로젝트 폴더를 GitHub 저장소에 올립니다.
2. Render에서 새 Web Service를 만들고 해당 저장소를 연결합니다.
3. `render.yaml`의 설정을 사용합니다.
4. Render의 Environment Variables에 `MESHY_API_KEY`를 입력합니다.
5. 배포가 끝나면 Render가 제공하는 `https://...onrender.com` 주소를 학생들에게 공유합니다.

Render는 Web Service를 제공하고 환경 변수를 서비스에 설정할 수 있습니다.
실제 배포 전에는 학교의 외부 AI 서비스 사용 및 개인정보 처리 기준을 확인하세요.

### 주의
현재 작업 대기열은 한 서버 프로세스의 메모리를 사용합니다.
학교 수업에서 약 40명이 한꺼번에 사용하는 목적이라면 처음에는 서버 인스턴스 1개 + 동시 AI 작업 2개 정도로 운영하고,
사용량이 늘어나면 Redis/BullMQ 등의 외부 작업 큐와 영구 저장소를 추가하는 것이 좋습니다.
